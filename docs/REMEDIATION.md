# Audit remediation

The fixes address F01–F11 and the ten documentation/tooling observations in the original [audit](AUDIT.md). The audit remains a historical snapshot; its old source line numbers do not describe the reformatted implementation.

| Finding                             | Implemented change                                                                                                                                                                                                    | Regression evidence                                                                                       |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| F01: cross-document tool execution  | Every hosted operation and tool message is bound to a document session and registration; receiving content/page handlers reject stale identities; navigation/replacement cancels work                                 | Background cancellation tests; Chrome navigation/replacement and Firefox delayed-navigation browser tests |
| F02: provider key destination       | Background Save/Test retain keys only for the same origin; settings gets key-presence metadata and has explicit remove-key control                                                                                    | Background Save/Test/key removal tests; Chrome settings test                                              |
| F03: revocation during turns        | Abort active requests and recheck permissions/resources around each awaited model/tool operation                                                                                                                      | Revocation during model response and tool handler tests; Chrome browser revocation test                   |
| F04: grant write races              | All approval, individual revoke, and clear-all mutations share an extension queue                                                                                                                                     | Concurrent approval, stale-write revocation, and clear-all tests                                          |
| F05: incomplete disclosure          | Full prompt and schemas are inspectable; requested/effective scopes are displayed; MCP endpoint discovery and discovered-tool approval are separate; background enforces exact approved resources and prepared routes | Chrome disclosure checks; two-stage browser MCP flow; background resource/metadata tests                  |
| F06: unlisted model selection       | Provider adapter rejects a model other than the configured extension-visible model                                                                                                                                    | Actual background request test verifies no fetch                                                          |
| F07: dropped direct tool fields     | Validate/convert once in the provider adapter; validate tool-call envelopes                                                                                                                                           | Background/provider wire payload assertions                                                               |
| F08: incompatible size limits       | Shared public/internal limits; separate internal context/tool message budget; serialized request and UTF-8 response/result ceilings                                                                                   | Escaped 20,000-character context and full 64-KiB tool-result round-trip                                   |
| F09: invalid/colliding aliases      | Deterministic bounded aliases with reverse routing and explicit aggregate budget                                                                                                                                      | Long site/MCP names, collision, and aggregate rejection tests                                             |
| F10: MCP parsing/session failures   | Incremental SSE event framing, matching RPC IDs, bounded pagination, and one session-expiry reinitialization                                                                                                          | MCP transport and browser lifecycle tests                                                                 |
| F11: validation/response boundaries | Explicit supported schema subset, argument validation before calls, safe tool errors, valid request envelopes, byte-counted reads with cancellation                                                                   | Validator, provider failure/oversize, and background tool-error tests                                     |

Documentation now distinguishes tested behavior from unsupported features/platforms. SPEC and declarations define the supported schema subset, tool-call shape, actual size limits, and cancellation semantics. Duplicate capabilities are rejected as required by SPEC; context fields are deduplicated. SECURITY provides the maintainer-approved private address, `sudip@yama.com.np`.

Firefox instructions build the ignored unpacked directory before loading it. Browser discovery uses Puppeteer metadata with executable overrides. Packaging uses a development-only ZIP library instead of a system executable, derives archive versions from shared constants, and ignores generated XPI files. Static checks guard version drift and classic-script boundary constants. Formatter checks keep asynchronous UI and extension flows readable. Settings lists grants with individual revocation controls.

## Verification

The completed validation run passed 42 unit/background tests, the Chrome and Firefox integration suites, and the additional Chrome security suite. Firefox lint reported zero errors, notices, and warnings. `npm audit` reported zero vulnerabilities after updating development dependencies.

Use `npm run validate` for static/format checks, unit/background regressions, Mozilla lint, and Chrome/Firefox/security browser suites. Use `npm run pack` for development archives and `npm audit` for dependency advisories. Detailed coverage and limitations are in [CONFORMANCE.md](CONFORMANCE.md).

These changes cannot undo a page tool's already-started side effects, make in-page consent immune to visual spoofing, or guarantee that a remote tool's behavior matches its metadata. Real providers/MCP services and non-macOS environments remain outside the executed validation scope.
