# v1 validation record

The audited defects have regression coverage in the revised implementation. This record describes automated evidence, not an independent certification or full provider/MCP interoperability assessment. The supported schema subset and limits are part of SPEC sections 5 and 7.1.

Browser validation uses Chrome for Testing 152.0.7977.75 and Firefox 155.0.1 on arm64 macOS. Other operating systems, declared minimum browser versions, Android, and real MCP services have not been validated here. A real GPT-5.6 Sol tool round trip and the live Brave sample site were verified on 2026-09-12; see [PROGRESS.md](PROGRESS.md) for the scope and compatibility limitation.

Last updated 2026-10-02 for 1.0.0-beta.2, which added the rows from "Generate bounds and `limits`" down, one or more per SPEC section 13 item (4, 7, 8, and 25 to 35). Those rows cite unit tests by file and test name and browser suites by what they assert. **None of the features in those rows has been verified against a live provider:** every suite uses mock HTTP providers, a fake desktop agent, or an in-page stand-in for the extension. The self-hosted Ollama provider is the one exception in this release: `ARJUNAH_E2E_OLLAMA` ran its browser suite against a real server on 2026-10-01.

Run `npm ci`, install test browsers if needed, then `npm run validate`. `npm run test:e2e:hosted` covers the hosted wallet surfaces and `npm run test:e2e:widget` the standalone renderer; `npm run test:e2e:desktop` runs the desktop companion suite with a fake agent; `ARJUNAH_E2E_LIVE=<provider>` uses a real signed-in CLI. `npm run pack` produces unsigned development archives. Browser install commands select available versions; use `CHROME_PATH` and `FIREFOX_PATH` to reproduce particular binaries.

The browser fixtures and mock endpoints use no real account or credential. A passing test for visible context does not prove exhaustive extraction behavior across every page/layout. MCP scope excludes server-request handling, OAuth, resources, prompts, sampling, and transport resumability. Schema validation intentionally rejects unsupported assertions rather than claiming all JSON Schema dialects.

See [REMEDIATION.md](REMEDIATION.md) for the audit-to-fix mapping and [AUDIT.md](AUDIT.md) for historical findings.

The browser suites stage disposable extension copies with a test-only provider transport redirect. Production endpoint validation still runs against the canonical OpenAI URL, and no live credentials or real provider traffic are used in those suites.
