## 2026-09-19 — naming, `window.ai.arjunah`, `enable()`

- The project, protocol, extension, and companion are **अर्जुनः** (romanized _Arjunah_; अर्जुनः कृष्णं पश्यति, "Arjuna sees Krishna": the extension sees both the AI and the human, so the website does not have to). Every user-visible title, label, and document says अर्जुनः; code, paths, and identifiers use the ASCII slug: npm package `arjunah`, bin `arjunah-desktop`, env prefix `ARJUNAH_*`, page events `arjunah:ready` / `arjunah:conflict`, widget host id `arjunah-extension`, bridge channel `arjunah-v0.1`, progress event `arjunah-progress`, bridged MCP server `arjunah` (`mcp__arjunah`), Firefox add-on id `arjunah@open-web.dev`, icon `src/icons/arjunah.svg`, types `types/arjunah.d.ts`, release archives `arjunah-<browser>-v<version>`.
- The page API lives at `window.ai.arjunah`. `window.ai` is a shared extensible namespace (created as a plain non-writable object when absent, reused when another actor already created one), so other extensions can coexist under their own keys; `arjunah:conflict` fires only when `window.ai.arjunah` exists or `window.ai` is not an extensible object. The root object is wallet-shaped: `isEnabled()` (a level 1 or 2 grant exists), `enable()` (defaults to level 1 and resolves to a **session** carrying `grant`, `permissions.query()`, `providers`, `models`, `context`), `disable()` (drops the origin's grant), plus the level 0 `site` and `chat` that need no grant. A page cannot reach `models`, `providers`, or `context` without a session; a session kept across `disable()` gets `PERMISSION_REQUIRED`.
- The companion's data directory is `arjunah` under the OS application-support folder (`ARJUNAH_DESKTOP_HOME` overrides it). This is the first public release, so the store carries no migration code.
- Documents now say _the extension_ (defined in SPEC section 1 as the browser extension) instead of the jargon term for it; SPEC section 1 introduces the three access levels before section 3 uses them. Code identifiers such as the internal error class and bridge method names are unchanged.
- Verified: `npm run check` (98 tests), Chrome E2E (7 provider requests), Chrome security E2E, Firefox E2E (6 provider requests, add-on id `arjunah@open-web.dev`), desktop E2E (2 agent runs), Firefox lint (0 errors/notices/warnings), and `npm run pack` built `dist/arjunah-chrome-v0.4.0.zip` and `dist/arjunah-firefox-v0.4.0.xpi`.

## 2026-09-13 — persistent agent threads, thinking, context sizes

### Scope

- **Threads (SPEC 12.3.1).** Each open hosted chat has a random conversation id; the extension sends it as `threadId` and releases it with `DELETE /api/threads/<id>` on reset, registration change, or navigation. The companion keeps one agent thread per id (handle, long-lived scratch directory, system-prompt/tool hash, messages seen) and resumes the agent's own session: Codex `exec … resume <thread_id> -` (no longer `--ephemeral`), Claude Code `--session-id`/`--resume` (no longer `--no-session-persistence`), OpenCode `--session <id>`. Later turns send only the new messages (`buildContinuation`). Provider/model/system-prompt changes or a shortened conversation start a fresh thread; idle threads expire after 30 minutes; Codex rollouts and Claude Code project transcripts are deleted when a thread ends.
- **Thinking.** `reasoning: { effort }` on `models.generate` and on hosted turns (widget header picker, shown when the model lists `reasoningLevels`), mapped to OpenAI `reasoning_effort`, Codex `model_reasoning_effort` (+ `model_reasoning_summary=detailed`), Claude Code `--effort`, OpenCode `--variant`. Reasoning summaries (Codex `reasoning` items, Claude thinking blocks, OpenCode reasoning parts) stream as `agent.reasoning`; Claude's `thinking_tokens` estimates stream as `agent.thinking`. `usage.reasoningTokens` and `usage.cachedTokens` are filled from every provider that reports them.
- **Context sizes.** Per-model `contextWindow` and `reasoningLevels`: Codex from `~/.codex/models_cache.json` (272k, low…max), OpenCode from `opencode models --verbose` (limits, reasoning, image input → per-model vision), Claude Code learned from `modelUsage.contextWindow` after the first run (1M for Opus 5 [1m]), OpenAI from the published catalog for the known slugs. The widget footer shows a context meter (last prompt tokens / window), cached and thinking tokens. Claude Code's `rate_limit_event` (5-hour and 7-day utilisation) becomes the provider quota, returned with each answer and stored so the widget and popup show it immediately.
- **Claude Code adapter** now uses `--output-format stream-json --verbose` and always passes an explicit `--mcp-config` (an empty server list when no bridge is needed). Without it Claude Code loaded the user's own MCP servers into website runs; that is fixed.
- **Codex sandbox profile** changed from a blanket home-directory deny (which also blocked the `stat` Codex needs to resolve its saved session) to a per-entry deny of every top-level home folder except `.codex`, plus a deny on listing the home directory itself. Verified with `sandbox-exec` probes: session file read and directory walk OK, `~/Documents`, `~/.zshrc`, and `ls ~` denied.

Completed commands and reasoning also come back on the result (`steps`, `reasoning`) and are stripped before anything reaches a page.

- Settings Test connection now verifies actual generation with a synthetic tool definition; failed, empty, or tool-only probe responses are not reported as success. It does not use page context, invoke site tools, or save settings. The selected model is preserved when loading model suggestions.
- The command-line live check now exercises the production adapter across a complete synthetic function-call/result round trip.
- Browser fixtures were stale: they attempted to save local endpoints despite production now allowing only OpenAI. Tests now stage a disposable extension copy that redirects only its provider transport to the local mock. Production source, endpoint enforcement, packaged artifacts, and the user's extension are not modified by the test transport. Firefox setup now handles the prefilled model and readonly endpoint correctly. The security test asserts foreign endpoint rejection without overwriting the saved credential.
